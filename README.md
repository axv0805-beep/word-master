# 词芽 · 背单词

一个**手机优先、可离线**的背单词 Web App（PWA），完整实现需求清单里的模块与功能，界面参考万词王、百词斩等产品的交互习惯。

- **技术栈**：React 18 + TypeScript + Vite 5 + Tailwind CSS 3 + Zustand
- **词书**：内置小学核心词（819 词，人教版 3–6 年级 8 册合并）、四级核心（2607 词）、六级（2345 词）、高考 3500（3883 词）、中考核心词（2135 词），共 **11,789 个词条**，全部打包在本地，离线可用
- **无需后端**：所有学习数据存在浏览器本地（localStorage），可导出/导入备份

## 快速开始

需要 Node.js 18+（本项目在 Node 22.17 上验证通过）。

```bash
# 安装依赖（npm / pnpm 任选）
npm install          # 或 pnpm install

# 开发模式，浏览器打开 http://localhost:5173
npm run dev

# 生产构建（产物在 dist/）
npm run build

# 本地预览构建产物
npm run preview
```

> **注意：不要直接双击 `dist/index.html`。** 生产构建是 ES module + PWA，`file://` 协议下浏览器会按 CORS 拦掉脚本/样式，Service Worker 也无法注册，页面会白屏。请用 `npm run dev` / `npm run preview`，或用下方桌面版。

> 手机上体验：让手机和电脑处于同一局域网，用手机浏览器访问电脑的 `http://<电脑IP>:5173`（只适合预览）。
> 想真正「装成 App」（全屏、离线），需要 HTTPS：推到 GitHub 后用自带的工作流部署到 GitHub Pages，手机浏览器打开 Pages 地址 →「添加到主屏幕」。详见 [docs/打包与安装.md](docs/打包与安装.md)。

### 桌面版（Windows exe）

项目内置了 Electron 壳，会把页面放进一个手机比例的窗口里，可缩放，默认窗口 430×900，画面居中（手机端布局不变）。

```bash
# 开发调试：构建后直接开窗口
npm run electron:dev

# 打包免安装桌面程序
npm run package:desktop
```

产物：

| 路径 | 说明 |
|---|---|
| `release/词芽-win32-x64/词芽.exe` | 双击运行（整个文件夹就是程序，别只拷 exe） |
| `release/词芽-桌面版.zip` | 整个程序目录的压缩包，方便拷贝/分发 |

> 桌面壳内置了一个只监听 `127.0.0.1` 的静态服务器，所以不会再遇到 `file://` 的白屏问题；F12 可打开开发者工具。
> 首次打包会下载约 110 MB 的 Electron 运行时到 `.electron/`（已加入 `.gitignore`），之后复用。

### 安卓版（APK）

原生 WebView 壳 + `WebViewAssetLoader`（把 `dist` 当作虚拟域名 `https://appassets.androidplatform.net/assets/www/` 提供，绕开 `file://` 的 CORS），页面里调起的发音走系统 `TextToSpeech`（WebView 没有 Web Speech API）。

```bash
npm run package:android
```

产物：`release/词芽-安卓.apk`。传到手机点开安装即可（系统会提示「未知来源」，选择允许）。

> 本机工具链已经装好：Android SDK 与 Gradle 8.7 在 `D:\A-WWW\DS-harness\android-toolchain`，签名钥匙在 `D:\A-WWW\DS-harness\.android`（别删，删了覆盖安装就会失败）。换机器时按 [打包与安装](docs/打包与安装.md) 里的命令重装。

> 已经部署好的站点也带了安装包：[下载最新版 APK](https://axv0805-beep.github.io/word-master/download/latest.apk)（约 2.9 MB），手机上打开这个链接直接下载。

#### 应用内更新

装过一次之后就不用再手动找安装包了：

1. 设置 → 关于 →「检查更新」，原生侧会去读站点上的 [`version.json`](https://axv0805-beep.github.io/word-master/version.json)
2. 有新版就点「立即更新」，APK 下载到缓存目录后自动拉起系统安装器
3. 覆盖安装即可，学习记录和设置都存在 WebView 的 localStorage 里，不会丢

也不用每次都自己想起来去点：进应用 1.2 秒后有新版本会从底部升起提醒（最多每 6 小时自动查一次，可以「稍后再说」静默 6 小时或「跳过这个版本」永久静音），下载中可以收起，进度在设置页继续。

下载本身也做了加固：服务器支持 `Range` 就切 4 段并行拉（速度更快），每段落在 `cacheDir/update/*.part` 里，网络断了、重试、甚至应用被杀掉，下次都从已经下到的位置接着传；重新打开应用会显示「下载已暂停 + 已下载多少」，点「继续下载」接着下。下完会校验大小、`PK` 头和 `version.json` 里的 `sha256`，坏包直接删掉重下。

发版时只要改 `android/app/build.gradle` 的 `versionCode`（+1）和 `versionName`（或者直接跑 `npm run bump:android`），再跑一次 `npm run package:android`——脚本会顺手更新 `public/version.json`、把 APK 发到 `public/download/`，推上去就生效。

没有 Android SDK 的机器走云端：Actions →「打包安卓 APK 并发布更新」→ Run workflow，一次跑完「版本号 +1 → 打 APK → 发布 → 提交 → 部署 Pages」。签名用仓库 secret `ANDROID_KEYSTORE_BASE64` 等注入（不配的话每包签名都不同，只能全新安装），细节见 [打包与安装](docs/打包与安装.md)。

> 页面资源是打包进 APK 的（见 `WebViewAssetLoader`），所以纯 Web 层的改动（界面、动画、文案）也得重新打包 APK 才会到手机上；只推 gh-pages 只影响浏览器访问的网页版。

> 首次点「立即更新」时系统会问是否允许「词芽」安装应用（Android 8+ 的未知来源限制），允许一次即可。

### 首次进入的学习计划引导

第一次打开会自动进入三步引导（老用户已有学习数据则不会被打扰，可在「设置 → 学习计划」里随时重走）：

1. **选择要背的词书** —— 内置 4 本 + 自己导入的词书，带词数与已学进度
2. **设定每日目标 + 每轮单词数** —— 10 / 20 / 30 / 50 / 100 快捷档位 + ± 微调（5–300）。**每轮单词数的可选档位随每日目标实时变化**（最低 10，最高不超过目标）；选定过程中就实时显示"以这个速度约多少天背完、每天几轮"
3. **自动生成计划** —— 显示预计多少天背完、折算成"约几周/几个月"、预计完成日期，以及每天大约要完成几轮；确认后写入设置并可直接「开始第一轮」

之后首页的「当前词书」卡片会一直显示"每天 X 词 · 预计还需 Y 天背完"，设置页也有完整的计划卡片。

> 天数口径：`已学词数` 会从总词数里扣掉（重设计划时算的是"还剩多少"），按 `ceil(剩余 ÷ 每日目标)` 向上取整，第 1 天算今天，所以"1 天"= 今天完成。
> 每天的轮数按 `ceil(每日目标 ÷ 每轮单词数)` 估算；因为每轮上限 = 每日目标，所以每天至少 1 轮、不会出现"一轮就超过当天目标"的情况。

### 答完一题后的「词形变化」与「易混词」

答题反馈卡下方会自动补两张卡片（只在词库里真实存在的词条上展示，没有则整块不出现）：

- **词形变化**：按词性分组列出它的名词 / 动词 / 形容词 / 副词形式，每条都带词典里真实的中文释义与发音。
  例：`create → 名词 creation、creativity；形容词 creative`
- **易混词**：拼写或发音相近、容易记混的词，并标注理由（**形近** / **音近** / **同尾**）。
  例：`effect → affect；principle → principal；desert → dessert`

**怎么做到不瞎编的**：内置词库只有「单词 + 释义」，没有词形表。所以这里用 **规则推导 + 词库验证**：

1. 用英语构词规则从词头生成候选（含去 e、y→i、双写辅音等拼写还原）
2. **只在词库里真实存在的词条上落地**——每个形式都带着词典里真实的中文释义，绝不凭空造词
3. 三道守卫压掉"真词误报"：屈折规则按词性收窄（否则 `care` 加比较级 `-er` 会拼出 `career`）、词性未知时禁用易撞车的短后缀、同族补充要排除"更属于另一个词"的候选（`happening` 属于 `happen`，不属于 `happy`）

易混词用编辑距离 + 音标相似度 + 前后缀重合度打分，所以能找出 `effect / affect` 这种首字母不同的经典易混对。
距离 2 内不够 3 个时，会用距离 3 但相似度达标的词补齐（`abandon → abundant`），补进来的候选要同时满足最低分、最短长度与首尾重合门槛。

**覆盖率（固定采样 497 词实测）**：约 **90.7%** 的词能拿到易混词，**21.1%** 能拿到词形变化，两者都没有的约 **8.2%**——
词库里确实没有相关数据时，反馈界面会给一行说明（"词典里没有收录「xxx」的其它形式或易混词"），而不是让你以为功能没生效。
覆盖率有回归测试兜底（`src/tests/coverage.test.ts`），掉下去会直接测试失败。

### 四种题型

1. **看中选英**：给中文意思 → 英文 4 选 1
2. **看英选中**：给英文单词（含音标）→ 中文 4 选 1
3. **听音辨义**：播放发音 → 中文 4 选 1（可重复播放）
4. **拼写题**：给中文意思 → 键盘拼写，支持「提示一个字母」与「拼读」

干扰项从同词书内挑选，优先词长相近、词性一致的词，并保证 4 个选项互不相同、释义不与正确答案重复。

## 测试与验收

```bash
npm run verify        # 词书校验 + 类型检查 + 179 个测试 + 生产构建
npm run verify:ui     # 真实 Chrome 里校验交互（需先 build），截图输出到 artifacts/
npm run verify:all    # 两者一起跑
```

覆盖内容：

- **出题引擎**：4 种题型的选项数量/唯一性/必含正确答案；用真实四级词书连续出 3000 题不出现异常；拼写判题（大小写、空格、短语）
- **轮次调度**：4 种错题重现策略各自的插入位置；同一单词一轮内最多重现一次；首答正确率与总体准确率分别统计
- **字母顺序**：排序、首字母统计、指定字母起点、取题到头循环
- **错题与进度**：错误累加、连对清除、SRS 间隔、掌握判定
- **统计**：每日累计、连续打卡（今天没练不清零）、成长曲线补空缺、评级、成就解锁
- **端到端**：答题 → 错题本 → 统计 → 轮次历史 → 导出/导入备份的完整链路
- **本地数据容错**：持久化数据残缺/类型损坏时逐字段回退默认值，不会出现「每日目标 0 / 题」这类问题
- **问候语**：8 个时段（凌晨/早上/上午/中午/下午/傍晚/晚上/夜安）各配多套说法，问候与叮嘱两截都随时间变化；同一天内文案稳定、跨天轮换；只在时段分界触发更新（不是每秒轮询），从后台切回前台会重新校准
- **界面冒烟（jsdom）**：六个页面渲染、底部导航切换、出题、对错反馈、错题写入；并有两项结构性回归检查——背景装饰层必须是空元素、不得包住应用内容，可交互控件不得被 `aria-hidden` 祖先包裹
- **真实浏览器（`verify:ui`）**：装饰层结构、页面可滚动、按钮命中测试（`elementFromPoint` 必须是按钮本身）、底部导航真实点击跳转、开始答题并出现反馈、深色主题生效、控制台无报错

> 为什么两层都要有：jsdom 的 `fireEvent` 直接派发事件、**绕过命中测试**，所以"有没有被别的元素盖住"这类问题只有真实浏览器查得出来；而真实浏览器跑得慢、不适合覆盖全部逻辑，两者互补。

## 词书数据

内置词书来自开源项目 [qwerty-learner](https://github.com/RealKai42/qwerty-learner) 的公开词库，**仅供个人学习使用**。

`scripts/fetch-dicts.mjs` 做了这些清洗（原始数据里混着若干非单词写法，直接出题会破坏选项与拼写）：

| 原始写法 | 处理后 |
|---|---|
| `bike = bicycle`、`grey / gray` | 拆成多个独立词条 |
| `understand understood understood`、`ambassador ambassadress` | 按词形相似度折叠为原形 |
| `mobile phone`、`as soon as` | 保留为短语词条 |

重新生成词书：`npm run fetch-dicts && npm run verify-dicts`。
下载依次尝试 `ghproxy.net` / `gh-proxy.com` / GitHub 原始地址，并回退 GitHub contents API。

### 导入自己的词书

词书页 →「导入自定义词书」，支持：

- **CSV / TSV**：`单词,中文释义[,美音[,英音]]`（首行表头会自动跳过）
- **JSON**：`[{"w":"abandon","t":["放弃"]}]`，也兼容 `{"name":"...","trans":[...]}`、`{"word":"...","meaning":"..."}` 等常见格式
- **TXT**：每行 `单词 中文释义`

## 界面说明

底部五个标签：**首页 / 词书 / 错题 / 统计 / 设置**，答题页为全屏沉浸模式。

- **首页有两副面孔**：默认是「打卡页」（右上角小树芽、居中大号打卡天数、当前词书进度、新学词 / 复习词、开始学习）；点右上角按钮会形变成「水滴 + 连续天数」，同时切到经典版（今日目标圆环、本轮单词数、速览、词书、错题、成长曲线），再点一次回到打卡页。选择记在存档里（`settings.homeView`），下次打开还是上次那副面孔；两副面孔共用同一份统计口径，切换是按钮形变 + 整页交叉淡入，减少动效时自动降级为直接切换。

- 7 套主题配色（青芽 / 极夜 / 极光 / 熔金 / 晨雾 / 樱粉 / 海盐），设置页点选即时生效并记入本地存档；默认浅绿「青芽」
- 品牌面片用渐变 + 顶部弧光，卡片为半透明毛玻璃（backdrop-filter）、导航栏带弧形选中指示器
- 桌面浏览器打开时会居中显示 480px 手机框，方便预览手机效果
- 答对有弹跳动效与自动朗读，答错有抖动反馈并立即记录错题

## 离线与隐私

- 词书、页面资源都由 Service Worker 缓存，装到主屏后可离线使用
- 所有数据只存在你自己的浏览器里，不上传任何服务器
- 换设备用「设置 → 导出备份」得到 JSON 文件，在新设备「导入备份」即可恢复

## 已知限制

- 「真人拆音节领读」用系统语音合成的逐字母拼读替代，实际音质取决于设备语音包；开启「在线真人发音」可获得更好的整词发音
- 词书只有英文→中文方向，源数据不含例句、词根词缀，因此未做这两项，避免编造内容
- 无浏览器端自动截图，界面观感需要你实际打开确认
