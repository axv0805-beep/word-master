# 协作者怎么发版（签名怎么给）

结论先说：**别把钥匙文件发给协作者，把钥匙放进仓库 secret，让协作者只点「Run workflow」。**

APK 的签名决定了「能不能覆盖安装」：同一台手机上，新包必须和已装的包用同一把钥匙签，否则系统只肯全新安装，用户的学习记录（存在 WebView 的 localStorage 里）就跟着没了。所以协作者打包也必须用你这把钥匙——但「用你的钥匙」不等于「把钥匙给他」。

## 一、推荐做法：钥匙进 secret，协作者只触发流水线（10 分钟配一次）

### 1. 给协作者开权限

仓库 → Settings → Collaborators → Add people → 选 `Write`。
`Write` 就能手动触发 Actions，但**看不到也改不了 secrets**（只有仓库所有者/管理员能管理）。

### 2. 你在自己电脑上把现有钥匙导成 base64

当前这版 APK 用的是本机工具链里的 debug 钥匙，位置：

```
D:\A-WWW\DS-harness\.android\debug.keystore
```

在 PowerShell 里执行（把结果整段复制走，这就是 secret 的内容）：

```powershell
$path = "D:\A-WWW\DS-harness\.android\debug.keystore"
[Convert]::ToBase64String([IO.File]::ReadAllBytes($path)) | Set-Clipboard
```

顺手确认一下这把钥匙的指纹和线上包一致（应该看到 `CN=Android Debug`）：

```powershell
& "C:\Program Files\Java\jdk-21.0.10\bin\keytool.exe" -list -v `
  -keystore "D:\A-WWW\DS-harness\.android\debug.keystore" `
  -storepass android -alias androiddebugkey | Select-String "SHA256"
```

### 3. 把 4 个 secret 写进仓库

用 `gh`（已登录的情况下最省事）：

```bash
gh secret set ANDROID_KEYSTORE_BASE64 --repo axv0805-beep/word-master < 钥匙base64.txt
gh secret set ANDROID_KEYSTORE_PASSWORD --repo axv0805-beep/word-master --body "android"
gh secret set ANDROID_KEY_ALIAS         --repo axv0805-beep/word-master --body "androiddebugkey"
gh secret set ANDROID_KEY_PASSWORD      --repo axv0805-beep/word-master --body "android"
```

> debug 钥匙的密码和别名是 Android 工具链的固定值（`android` / `androiddebugkey`），保密性全靠钥匙文件本身，所以**不要**把 `debug.keystore` 提交进仓库，也不要在群里发。

（可选）如果仓库 Settings → Actions → Workflow permissions 还是「Read repository contents」，流水线提交会被 403：再配一个 `RELEASE_TOKEN`（细粒度 PAT，Contents: Read and write），工作流里已经支持。

### 4. 协作者发版

仓库 → Actions →「打包安卓 APK 并发布更新」→ Run workflow：

- `bump` 保持 `true`：版本号自动 +1
- `notes` 填更新说明（留空则沿用上一版）

流水线会一次跑完：版本号 +1 → 构建 web → 拷进 APK 资源 → Gradle 打 APK → 同步 `public/download/` 与 `public/version.json` → **用 gh 发 GitHub Release（APK + version.json）** → 提交推送 → 触发 Pages 部署。协作者全程没碰过钥匙。

## 二、协作者必须在自己电脑上打包时

这种情况才需要给文件，但要**走密码管理器的一次性分享**（1Password / Bitwarden Send / 临时加密压缩包+另发密码），不要用微信、QQ、邮件直接发。

给他两样东西：

1. `debug.keystore` 文件
2. `android/keystore.properties`（放在项目里，已被 `.gitignore` 挡住）

```properties
storeFile=keystore.jks
storePassword=android
keyAlias=androiddebugkey
keyPassword=android
```

`android/app/build.gradle` 的签名钩子读的就是这个文件：存在就用它覆盖默认签名，不存在就退回 AGP 自动生成的 debug 钥匙。他跑 `npm run package:android` / `npm run release:android` 打出来的包就能覆盖安装。

用完记得让他删掉本地这两个文件。

## 三、安全提醒（重要）

- 现在这一版用的是 **debug 签名**（`CN=Android Debug`），密码是公开的 `android`。它挡不住「谁知道钥匙文件谁就能签名」，只适合小范围内测。
- 等要正式分发（上架/大规模推广）时，建议生成一把正式的 release 钥匙并离线保存：换钥匙会让所有老用户**卸载重装一次**，所以最好的时机是现在用户还少的时候；拖得越久代价越大。
- 钥匙泄露的处理：生成新钥匙 → 用新钥匙发版 → 通知用户卸载重装（签名变了无法覆盖）。以后如果上架 Google Play，可以改用 Play App Signing 把签名托管给 Google。
- 永远不要：把 `*.jks` / `*.keystore` / `keystore.properties` 提交进仓库（`.gitignore` 已经挡了）；把钥匙贴在 issue、聊天记录、CI 日志里。
