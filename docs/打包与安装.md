# 打包与安装

本文说明如何把「词芽」变成两种可直接使用的形态：

1. **Windows 桌面程序**（免安装 exe，电脑上查看/使用）
2. **手机 PWA**（部署到 GitHub Pages 后「添加到主屏幕」，全屏、离线）

> 先说结论：本项目是 Web 应用，**不能双击 `dist/index.html` 打开**。`file://` 下浏览器会拦截 ES module 脚本和样式，Service Worker 也无法注册，结果就是白屏。所有方式都必须通过 http/https 访问。

---

## 一、Windows 桌面版

### 1. 打包

```bash
npm install          # 首次
npm run package:desktop
```

脚本会依次做：

1. `npm run build` 生成 `dist/`
2. 首次运行时下载 Electron 33 运行时（约 110 MB）到 `.electron/`
3. 组装到 `release/词芽-win32-x64/`，写入程序图标和版本信息
4. 额外打一个 `release/词芽-桌面版.zip`

产物：

```
release/
├── 词芽-win32-x64/
│   ├── 词芽.exe        ← 双击这个
│   ├── resources/app/    ← 页面代码 + dist
│   └── *.dll, *.pak ...  ← Electron 运行库
└── 词芽-桌面版.zip      ← 整个目录的压缩包
```

> **分发时请发整个文件夹（或 zip）**，不要只发 `词芽.exe`：它依赖同目录下的 dll 和 `resources/`。

### 2. 开发调试

```bash
npm run electron:dev
```

直接开窗口，改前端代码后 `npm run build` 重新构建、再启动即可。窗口里按 **F12** 打开开发者工具。

### 3. 桌面版的行为

- 窗口默认 430×900（手机比例），可自由缩放/最大化，画面始终按 480px 宽居中
- 启动时在 `127.0.0.1` 的随机端口起一个只读静态服务，窗口加载它，因此绕开了 `file://` 的限制
- 外部链接用系统浏览器打开
- 单实例：重复双击只会聚焦已打开的窗口
- 学习数据存在 Electron 的用户数据目录（`%APPDATA%\<应用名>` 下），卸载时删除该目录即可清空

### 5. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 双击后 SmartScreen 提示「未知发布者」 | 没有做代码签名，点「更多信息 → 仍要运行」即可 |
| 打包时下载 Electron 失败 | 手动下载 `https://npmmirror.com/mirrors/electron/33.2.0/electron-v33.2.0-win32-x64.zip` 放进 `.electron/` 后再跑一次 |
| 想换图标 | 替换 `build/icon.ico` 后重新 `npm run package:desktop` |
| 想清空重来 | 删掉 `release/` 和 `.electron/`，再打包 |

## 二、安卓 APK（直接装到手机）

想要一个「下载就能装」的文件，而不是通过浏览器添加到主屏幕，就用 APK。

### 1. 打包

```bash
npm run package:android
```

产物：`release/词芽-安卓.apk`（约 2 MB）。

### 2. 装到手机

1. 把 APK 传到手机（微信文件传输助手 / QQ / 数据线都行）
2. 点开安装，系统提示「未知来源应用」时允许这一次
3. 桌面出现「词芽」，点开就是全屏应用

> 现在是 debug 签名，自己用完全没问题；如果要上架应用商店，需要生成正式签名（keystore）再 `assembleRelease`。

### 3. 云端打包（GitHub Actions，不用装 Android SDK）

本机没有 Android SDK / Gradle 时，让 GitHub 的机器帮你打：

1. 仓库 **Settings → Actions → General → Workflow permissions**，选「Read and write permissions」（工作流要自己提交 APK 和 `public/version.json`）
2. 同一页的 **Secrets and variables → Actions**，按需加签名用的 secret（**强烈建议**，见下）：

   | Secret | 值 |
   |---|---|
   | `ANDROID_KEYSTORE_BASE64` | keystore 的 base64：macOS/Linux `base64 -w0 ~/.android/debug.keystore`；Windows PowerShell `[Convert]::ToBase64String([IO.File]::ReadAllBytes("$env:USERPROFILE\.android\debug.keystore"))` |
   | `ANDROID_KEYSTORE_PASSWORD` | `android`（默认 debug keystore 的口令） |
   | `ANDROID_KEY_ALIAS` | `androiddebugkey` |
   | `ANDROID_KEY_PASSWORD` | `android` |

3. Actions 页 →「打包安卓 APK 并发布更新」→ **Run workflow**，勾上「版本号自增」，需要的话填更新说明
4. 一次跑完：版本号 +1 → 构建 web → 打 APK → 发布到 `public/download/` → 写 `public/version.json` → 提交推送 → 调用 `deploy-pages.yml` 让站点一起上线

> 为什么要传签名：APK 升级要求签名一致。没配 secret 时工作流用 runner 上的临时 debug 签名，每次都不一样，只能在没装过的手机上全新安装，覆盖升级会提示「应用未签名冲突 / 未安装」。
> 这台机器以前打出来的包是 `~/.android/debug.keystore` 签的，把它填进上面的 secret，签名就和历史版本对上了——覆盖安装成功、学习数据不丢。

### 4. 更新机制

装好之后不用再手动找安装包：

1. 打开 设置 → 关于 →「检查更新」
2. 原生侧请求站点上的 `version.json`，把它的 `versionCode` 和本机 APK 比较
3. 有新版就显示新版本号和更新说明，点「立即更新」下载 APK 并拉起系统安装器
4. 覆盖安装后学习记录、错题本、设置都在（localStorage 不受影响）

发版流程（本地）：

```bash
# 1. 版本号 +1（versionCode 与 versionName 末位各 +1）
npm run bump:android

# 2. 打包（脚本会同时写 public/version.json、把 APK 拷到 public/download/）
npm run package:android

# 3. 推送，站点和更新清单一起上线
git add -A && git commit -m "release: 1.2.0" && git push
```

> 已经有构建好的 APK 时，可以只跑 `npm run publish:android <apk 路径> --notes "更新说明"` 来发布（云端工作流用的就是它）。
> 本机没有 Android SDK 就走上一节的「云端打包」，效果一样。

> 顺序别反：`version.json` 一旦上线，应用内「检查更新」就会把新版本推给所有人。要保证 `public/download/<新版本>.apk` 已经跟着一起推上去，否则点了更新会 404。
> 纯 Web 层的改动（界面 / 动画 / 文案）同样要重新打包 APK——页面资源是打进 APK 的，只部署 gh-pages 不会更新到手机上。

> 也可以临时用 `UPDATE_NOTES="本次更新说明" npm run package:android` 指定更新说明。
> 版本号只认 `android/app/build.gradle`，别在别处手改。

### 5. 实现方式

原生 WebView 壳，页面资源通过 `WebViewAssetLoader` 以 `https://appassets.androidplatform.net/assets/www/` 提供，因此不受 `file://` 的 CORS 限制，`HashRouter`、localStorage、发音都能正常工作。

| 文件 | 作用 |
|---|---|
| `android/app/src/main/java/com/cimiao/app/MainActivity.java` | WebView + AssetLoader + 返回键 + TextToSpeech 发音桥 |
| `android/app/src/main/AndroidManifest.xml` | 权限（含 REQUEST_INSTALL_PACKAGES）、FileProvider、横竖屏锁定、图标与主题 |
| `android/app/src/main/res/values/themes.xml` | 状态栏/导航栏取品牌绿 `#F1FAF3` |
| `scripts/build-android.mjs` | 本地打包：构建 web → 复制到 ASCII 暂存区 → Gradle 打包 → 写 version.json → 发布 APK |
| `scripts/android-release.mjs` | 发版公共逻辑：读版本号、写 version.json、发布 APK（本地与 CI 共用） |
| `scripts/publish-android.mjs` | 发布已有 APK：`npm run publish:android <apk> --notes "…"`（支持 `--dry-run`） |
| `.github/workflows/android.yml` | 云端打包：手动触发 → 版本 +1 → 打 APK → 提交发布 → 调 Pages 部署 |
| `public/version.json` | 更新清单：versionCode / versionName / APK 地址 / 更新说明 |
| `scripts/make-android-icons.py` | 从 `build/icon-source.jpg` 生成 5 档 mipmap 图标 |

> Gradle 在 `D:\A-WWW\DS-harness\android-build` 这份 ASCII 路径副本里跑，因为 AGP 在 Windows 上不接受中文项目路径。

### 6. 常见问题

| 现象 | 处理 |
|---|---|
| `Your project path contains non-ASCII characters` | 别在中文目录直接跑 Gradle，用 `npm run package:android`（它会复制到 ASCII 暂存区） |
| 首次构建卡在下载依赖 | 项目已把 Aliyun 镜像放在仓库列表最前面；断网会失败 |
| 装完打开白屏 | 检查 `android/app/src/main/assets/www/` 是否有 `index.html`，重新 `npm run package:android` |
| 想换图标 | 替换 `build/icon-source.jpg`，跑 `npm run icons` 后重新打包 |
| 云端工作流 push 被拒（`Resource not accessible by integration`） | Settings → Actions → General → Workflow permissions 改成「Read and write permissions」 |
| 云端打的包装不上，提示「应用未安装 / 签名不一致」 | 没配 `ANDROID_KEYSTORE_BASE64`，用的是 runner 临时签名；把 `~/.android/debug.keystore` 填进去 |

## 三、手机 PWA（装到主屏幕）

### 为什么不能直接用局域网 IP 安装

Service Worker / 可安装 PWA 要求**安全上下文**：`https://` 或 `localhost`。手机访问 `http://192.168.x.x:5173` 只是普通网页，能预览，但「添加到主屏幕」不会变成独立 App、也不能离线。

所以正式安装走 GitHub Pages（自带 HTTPS）。

### 1. 部署到 GitHub Pages

仓库里已经放好工作流 `.github/workflows/deploy-pages.yml`，推送 `main` 分支就会自动构建并发布。

首次需要手动开启一次：

1. 打开仓库 → **Settings → Pages**
2. **Build and deployment → Source** 选 **GitHub Actions**
3. 到 **Actions** 标签页，等「部署 PWA 到 GitHub Pages」跑完
4. 页面会给出地址，形如 `https://<用户名>.github.io/word-master/`

之后每次 `git push` 都会自动更新。

### 2. 手机上安装

**Android（Chrome / Edge）**

1. 用手机浏览器打开上面的 Pages 地址
2. 地址栏右侧出现「安装」图标，或菜单 →「安装应用 / 添加到主屏幕」
3. 桌面会出现「词芽」图标，点开是全屏、无地址栏

**iPhone（Safari）**

1. Safari 打开 Pages 地址
2. 点底部「分享」→「添加到主屏幕」→ 添加

> iOS 上需要先随便用一次（加载词书）再断网，离线才完整；PWA 的缓存策略已在 `vite.config.ts` 里配置（词书 JSON 走 CacheFirst，缓存一年）。

### 3. 局域网临时预览（不安装）

```bash
npm run dev -- --host
# 或 npm run preview -- --host
```

手机浏览器访问 `http://<电脑IP>:5173`。仅用于看效果，不具备 PWA 的离线/全屏能力。

## 四、实现说明

| 文件 | 作用 |
|---|---|
| `electron/main.cjs` | Electron 主进程：本地静态服务 + 窗口 + 外部链接 + F12 |
| `scripts/electron-runtime.mjs` | 下载/解压 Electron 运行时、下载 rcedit |
| `scripts/electron-dev.mjs` | `npm run electron:dev` |
| `scripts/package-desktop.mjs` | `npm run package:desktop`：组装 + 图标 + zip |
| `build/icon.ico` | 程序图标（由 `public/icons/icon-512.png` 生成） |
| `scripts/make-icons.py` | 从 `build/icon-source.jpg` 生成网站/PWA 全套图标 |
| `scripts/make-android-icons.py` | 生成安卓 mipmap 图标（5 档） |
| `scripts/build-android.mjs` | `npm run package:android`：构建 + 暂存复制 + Gradle 打 APK |
| `android/` | 安卓 WebView 壳工程（MainActivity / Manifest / 主题） |
| `.github/workflows/deploy-pages.yml` | GitHub Pages 自动部署 |

打包不会修改 `src/` 和 `vite.config.ts`，前端代码与桌面壳、PWA 完全共用一份 `dist/`。
